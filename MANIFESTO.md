# Manifesto: Living Data

## The Problem That Has No Name

Every innovation in computing for the last 70 years has been built on top of the same silent assumption:

> **Data is passive. Code is active.**

Data sits still. Programs act on it. Data is moved, shaped, stored, and destroyed by external forces. It has no orientation, no history of being known, no sense of time, no internal state beyond its content.

This assumption is so deep it isn't taught. It is inherited. Every database, every API, every file system, every programming language treats data as inert material — a substance to be processed.

We are not arguing this model is wrong. We are arguing it is **incomplete** — and that its incompleteness is the source of a bottleneck that no amount of new tooling, new frameworks, or new infrastructure can resolve. Because all new tooling inherits the same foundation.

---

## The Three Broken Assumptions

**1. Data needs storage to persist.**

Current reality: remove the storage layer, data ceases to exist.

What we're replacing it with: data can persist through internal coherence — the way a living cell doesn't need a shelf to sit on. Existence is a property of what data *is*, not where it's *kept*.

**2. Data needs external agents to have meaning.**

Current reality: meaning is assigned by code that interprets data. Strip the code, and data is just bytes.

What we're replacing it with: data carries its own interpretation as an intrinsic property. The *why* and the *what* are inseparable.

**3. Observation is neutral.**

Current reality: reading data leaves both the data and the reader unchanged. Access is free. Observation costs nothing.

What we're replacing it with: observation is a state-changing act. Every encounter permanently modifies both the data and the observer. Deniability — the ability to pretend an encounter did not happen — is structurally impossible.

---

## What Living Data Is

Data with three intrinsic properties that do not depend on infrastructure:

**Existence** — the capacity to persist through coherence, not location.

**Epistemic State** — the capacity to believe, doubt, and hold uncertainty as a native condition, not an error state.

**Temporal Orientation** — the capacity to carry history and lean toward futures — to remember, and to hope.

---

## The Direction of Travel

We are not building a product. We are building primitives — foundational behaviors so basic that, once adopted in one place, their absence everywhere else becomes intolerable.

The path a true primitive takes:

1. Contained environment — embedded in one system where it cannot be ignored
2. Repeated necessity — users encounter the need for it again and again
3. Expectation forms — its absence begins to feel like a missing feature
4. Standardization — it becomes part of how systems are built

We are at step one. Deliberately.

---

## What Comes Next

Primitives are defined one at a time. Each one is:
- Precise enough to implement
- Distinct enough to be irreplaceable
- Consequential enough that removing it breaks something real

The first primitive is **WITNESS**. Everything else is built from there.
